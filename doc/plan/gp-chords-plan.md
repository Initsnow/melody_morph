## 背景（为什么做）

当前 `gpchords` 识别算法存在已实测确认的问题：

- 主音加分（`annotate.py:194-195`）系统性偏向主音和弦，Am7（低音 A）被判成 C6/A；
- 低音权重只有 `0.05 × matched`，转位/相对和弦歧义判错（Dm7/F → F6）；
- 固定窗口（小节/半小节/拍）把一小节内的多个和弦混成一团（C+F → Fmaj9）；
- 时值加权 `max(duration_quarters, 1.0)` 让十六分音符与四分音符同权，跨窗延音（tie）被重复计权；
- 斜杠低音拼写错误（C7/A# 应为 C7/Bb）；
- 模板只有 21 种，缺 7b5、7#9、add11、11、13 等常用写法；
- 调性取全轨最常用的调号，忽略中途转调（真实样例：《无论如何 - 副本.gp》，A→C→A，转调点小节 50/57）；
- pychord 等候选列举库不解决"从候选中选一个"的问题，不接入；但其品质数据可作模板扩充参照。

## 第 2 步：修打分核心

- [x] 删除主音加分，调性只用于拼写与同分时的极小破平（破平顺序：分数 > 调内/主音 > 低音=根音 > 根音权重 > 模板更简 > 根音编号）
- [x] 低音加权定根音：低音音级权重放大 `BASS_WEIGHT_MULTIPLIER = 2.0`（远超原 `0.05 × matched`），低音=根音在同分时优先
- [x] 时值/延音加权修复：按真实时值计权（无 1.0 下限），延音延续音符不重复计权、时长并入延音起点；顺带修复 parser 里 `16th` 时值解析为 0 的 bug（GPIF 用 `16th` 而非 `Sixteenth`）
- [x] 斜杠低音拼写修复：按和弦品质度数拼写低音（C7/A# → C7/Bb），非和弦音低音回退调性拼写
- [x] 系数收进常量表：`UNMATCHED_PENALTY / MISSING_PENALTY / COMPLEXITY_PENALTY / BASS_WEIGHT_MULTIPLIER`（含吉他收敛分支的 0.8）
